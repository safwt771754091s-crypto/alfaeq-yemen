## Goal
User wanted the whole platform to work with no internet and to ship an Android
APK teachers can install.

## Offline: fonts were the only external dependency
`index.html` pulled Cairo+Tajawal from Google Fonts. Fetched the CSS with a
desktop UA, kept only the `/*arabic*/`, `/*latin*/`, `/*latin-ext*/` subsets (the
two Arabic families are variable fonts → one woff2 per weight), rewrote
`url()` to `./name.woff2`, saved under `public/fonts/` (11 files, 204 KB), and
linked `./fonts/fonts.css`. Also dropped the remote `@import` from the
DesignStudio HTML export. Added font exts to Workbox `globPatterns`. Result: no
network at all; SW precaches 25 entries. Font CSS uses relative `./` paths (not
`/fonts/..`) so it works under both the site root and Capacitor's
`https://localhost/`.

## Android APK (Capacitor 6)
Env has no Java/Android SDK. Install path:
- **JDK**: apt only has OpenJDK 21, but the Capacitor 6 Gradle (8.2.1/AGP 8.2.1)
  template needs Java ≤17. Downloaded Temurin **17** tar.gz from GitHub releases
  into `/workspace/tools/jdk17` (adoptium API 403s to urllib; curl GitHub direct).
- **SDK**: cmdline-tools zip → `/workspace/tools/android-sdk/cmdline-tools/latest`
  (chmod +x bin/*), then `sdkmanager --licenses` + platform-tools,
  platforms;android-34, build-tools;34.0.0. No `unzip` → used python zipfile.
- `android/local.properties` → `sdk.dir=/workspace/tools/android-sdk`.
- Icons: rendered the favicon SVG to all mipmap densities with cairosvg+PIL,
  incl. `ic_launcher_foreground` at 66% safe-zone for adaptive icons.
- Release signing: keystore **must live in `android/app/`** (gradle's
  `file()` resolves relative to the module dir, not the project root). Passwords
  read from env `KEYSTORE_PASSWORD`/`KEY_ALIAS`/`KEY_PASSWORD` (defaults for dev).
- Build: `cd android && JAVA_HOME=… ANDROID_HOME=… ./gradlew assembleRelease
  --no-daemon`. ~15s incremental, ~1m cold. Output
  `android/app/build/outputs/apk/release/app-release.apk` (~3.2 MB, signed,
  `ye.teacher.smart`, minSdk 22).

## Distribution gotcha
`vite build` **wipes `dist/`**, deleting any APK copied there. Correct order:
`npm run build` → `npx cap sync android` (to avoid bundling the APK inside the
app) → `gradlew assembleRelease` → copy APK into `dist/`. The in-app Settings
download card (`a[href="./smart-teacher.apk"]`) is hidden when
`window.Capacitor?.isNativePlatform?.()` is true, so the native app doesn't offer
to download itself.

## Repo hygiene
`.gitignore` now excludes `android/{.gradle,build,app/build,local.properties,...}`,
`download/`, `*.apk`, `*.keystore`, `*.jks` — the keystore is a secret and must
never be committed.

## PWA stale-cache fix (user reported "نفس التصميم الأول ما تغير")
The server was provably serving the new hashed bundle, but the user's device
kept the OLD app via the service-worker precache. Root cause: default Workbox
config precached index.html and served it cache-first, and the app had no update
handler, so a normal reload never picked up new builds.

Fixes:
- `vite.config.js` workbox: `skipWaiting` + `clientsClaim` +
  `cleanupOutdatedCaches`, plus NetworkFirst `runtimeCaching` for
  `request.mode === 'navigate'` (cache `alfaeq-pages`, 4s timeout) so
  navigations prefer fresh HTML yet still work offline.
- `src/main.jsx`: register `./sw.js` (PROD only) and reload once on
  `controllerchange` (guarded by `window.__swReloaded`) — auto-updates forever.
- `src/pages/Settings.jsx`: new "تحديث المنصة" card with `hardRefresh()` that
  unregisters all SWs + deletes all caches then reloads (keeps LocalStorage).

Caveat: an already-stale client runs the OLD bundle with no controllerchange
handler, so its first reload may need to happen twice; a hard reload
(Ctrl+Shift+R) or clearing site data guarantees it in one step.
